# ADR-0001: Baseline 2.8 四处编辑级自相矛盾修复

日期：2026-08-26 · 状态：Accepted · 触发：p0-wave3 闸实装后，G80-15/16/23/24 在真仓库上的红全部核实为 spec 本体缺陷（非解析器误红）。四处均为编辑级，不动任何结构决定；判据依据全部来自 spec 自己的冻结规则。

1. **§16.3 第三条切换判据**（原 3127 行）：`benchmark(shadow) 不劣于 benchmark(serving)` 正是 §69 Continuation Gate CI ②（G80-15）明令禁止且拿来当注入样例的原句——§69 冻结「覆盖此前一切『不劣于基线』的表述」，此行即"在别的章里以判据形态活下来"的那一处。改写为证伪形态：`未被证伪劣化于`，判据形态指向 §69 FAIL 侧。
2. **§69 Benchmark 声明表 `memory_security_lifecycle` 行**：「§55 名称」列写 "private memory poisoning lifecycle set"，§55 清单原名是 "memory security lifecycle set"。G80-16 要求 set_id 与 §55 集合清单逐名对齐。改为 §55 原名。
3. **G59-6 归位 §59.1**：`### G59-6 / Private Authority Boundary` 原在 §10.1，违反 §80.1.2 id 族章号绑定（G59-* 只在 §59.*），导致 G80-23②（锚 §59.1#G59-6 指空）与 G80-24①（族扫描差集）双红。整块移入 §59.1，§10.1 留指针不留第二份正文。
4. **§80.1 G80-32 行判据出处**：`§20.4` → `§20.4#G20-1`。`### G20-1 Snapshot Selection` 有 id 却从未被登记表以 #ID 引用，G80-24① 族扫描差集非空。

不修的：G80-15/16 未按 wave3 审查建议改期到 Phase>0——闸是对的，spec 修了红就消，改生效期才是调松定义（§80.1.2 对 G80-21 的批评原文）。
